# Flux Build v1.1.2 - Completion Report

Date: 23/10/2026
Branch: `feature/floating-buttons-spoof`
Scope: Android launcher and floating-button overlay. Java and Android resources only; no native
source changed.

## Delivered

- Side navigation drawer (`DrawerLayout` + `NavigationView`) with Home/Graphics/Interface/Tools/Help,
  a top-left hamburger, back-closes-drawer, checked-item sync, and the Navy-Slate / Electric Cyan
  palette.
- First-run device profiling (`DeviceAutoConfig`) for RAM, CPU cores and real screen size; 8 GB+
  High / 1440p (capped), 6 GB Medium / 1080p, below 6 GB Low / native; storage-permission retry;
  first-launch-only Options.ini write plus a "Re-run Auto-Configuration" action.
- App Theme Colors with independent accent/background/text roles, immediate themed rebuild,
  scroll preservation, contrast-aware swatch rings, reset-to-Flux, and a full surface ladder that
  follows a custom dark base.
- Advanced floating-button editor: "+" action picker for Keyboard Key / LMB / RMB, persisted new
  buttons, a selected-button-only corner resize handle with independent `widthDp`/`heightDp`,
  measured edit-toolbar gaps, and a larger invisible resize hit target.
- Required bug fix: `TouchControlConfig.load()` now preserves `enabled=false`, empty profiles and
  corrupt profiles instead of restoring the factory E/Q/W/R layout with `enabled=true`. The stock
  group panel is restored whenever the overlay is off or has no buttons.
- 29 new strings copied into all 13 locale folders; every locale now has the same 596 names as
  `values/`.

## Mistakes found and how they were addressed

1. **Stale APK after late source refinements.** The first build predated the final toolbar/theme
   edits. A final `./gradlew clean assembleDebug` was run after the last Java change; the APK
   timestamp and source timestamps were checked, then the artifact was verified again.
2. **White/cream swatch selection ring was invisible.** The selected ring used the accent, which
   disappears on a white chip. Each swatch now chooses a black or white ring from its own luminance.
3. **Theme change reset the page to the top.** Rebuilding the launcher lost the scroll position.
   The rebuild now captures `contentHost`'s scroll Y and restores it after the new page is built.
4. **Day + custom light text could become unreadable.** All offered text swatches are light, while
   the Day palette has light surfaces. Choosing light text with no custom base now supplies the
   Flux dark base and, if still unset, the cyan accent. The background guard now uses
   `ThemeHelper.palette()` instead of `getMode()`, so "follow the phone" in light mode is treated as
   Day. An explicitly chosen base or accent is never overwritten.
5. **Day cards kept white text on a white Button.** The touch-editor toolbar buttons now use a tonal
   background around their white labels instead of relying on the platform Button fill.
6. **Localized edit-toolbar labels could run under the +/- controls.** The fixed 58/62 dp gaps were
   replaced with gaps measured from the active locale's strings; the bar grows instead of clipping.
   Extremely narrow split-screen windows remain an edge case.
7. **The resize knob was too small for a finger.** The visible knob is 22 dp; the hit box is 36 dp
   and only exists for the selected button.
8. **The overlay read SharedPreferences in its draw loop.** The custom background flag and colour
   are now cached in the overlay constructor; the editor preview keeps the static helper.
9. **Tapping the gear while holding an LMB/toggle could strand input.** `enterEditMode()` now calls
   `cancelActivePress()` before it stops forwarding touches.
10. **Options.ini writes were not atomic.** The old writer truncated the live file before writing.
    It now writes a complete sibling and moves it over the target, so a crash/full disk cannot
    destroy an existing profile. The first-run guard also requires a detail-level key, so a bare
    Resolution-only file from the old launch path no longer suppresses the profile.
11. **A generated asset was nearly committed.** `android/app/src/main/assets/gamedata/DefaultOptions.ini`
    is generated by `scripts/build/android/package-android-zh.sh` and is intentionally ignored. A
    temporary `.gitignore` exception was reverted; the current APK still contains the 404-byte
    asset because the packaging step generated it.
12. **Feature annotations said 24/10/2026.** Today is 23/10/2026; the annotations were corrected.
13. **`ThemeColors.LEGACY_BUTTON_FILL` was private but referenced by the overlay cache.** It is now
    package-private, matching `DEFAULT_BUTTON_FILL`; the clean build confirms it.
14. **`stripDebugDebugSymbols` warned about every packaged .so.** This is pre-existing and does not
    fail the build; the libraries are already stripped/prebuilt. The APK was independently checked.

release (2 GB asset limit) or uploaded to a host that accepts it; the workspace also contains it at
`apk/GeneralsXZH-android-v1.1.2.apk`. No GitHub authentication is available in this environment, so
the repository itself was not pushed or tagged. The existing tracked
`apk/GeneralsXZH-android-v1.4.1.apk` was left untouched; the untracked v1.1.1 APK was moved out of
the repository to `/tmp/opencode/archive/`.
